# Phase 3.5 — Publishing Reliability & Recovery (beta.7)

## Delivered

- `/api/publishing/wake` invokes a publishing cycle; accepts only a short-lived HMAC signature generated by the Supabase Cron process, or the existing owner bearer key.
- Live due-only Supabase Cron `sniff-publishing-due-wake` runs every minute and sends an HTTP request only if a scheduled job is due within five minutes or overdue.
- Owner-only Publishing Health shows scheduled, published, failed, overdue, stalled and uncertain jobs; publishing history shows events.
- Only confirmed pre-Meta failures may be manually retried with an explicit confirmation. Any possible Meta publication attempt remains `needs_reconciliation`, with no automated retry.
- Existing 30-second worker polling and atomic claim remain in place. This is best effort on Render Free; no exact-time guarantee.

## Free-tier trade-offs

The wake starts up to five minutes before a due job and repeats while due. Render cold starts, outages, quotas, network timeouts and external Meta limitations can still delay or prevent publishing. No cron mechanism can promise exactly-on-time delivery on free hosting. The database is authoritative and posts are never automatically duplicated.

## Recovery policy

| State | Meaning / action |
| --- | --- |
| Scheduled / Overdue | Supabase job exists; Cron wakes the worker if configured. Check health and logs before manually acting. |
| Publishing / Stalled | Execution began. Do not retry or create a duplicate; investigate account/Meta first. |
| Published | Instagram media ID and timestamp recorded; no further publishing. |
| Failed | Error occurred before a Meta publishing request; resolve credentials/media problem, inspect audit, then owner may choose manual retry. |
| Needs review | Meta may have seen an operation; no automated or manual blind retry. Confirm Instagram outcome and reconcile safely. |
| Cancelled | No publication is attempted. |

## Rollback

To temporarily disable wake-ups without touching publishing data:
```sql
select cron.unschedule('sniff-publishing-due-wake');
```
To re-enable after rollback, execute the tracked script `db/phase35_cron_wake.sql` exactly once.

## Safety

- Owner key is encrypted at rest in Supabase Vault and never included in scheduled HTTP headers.
- Wake request carries only a timestamp and HMAC signature with a two-minute validity window.
- A captured signed request could be replayed during that short window; worker in-process lock plus PostgREST conditional claim prevent two instances from processing the same publication.
- If an Instagram request was issued but no acknowledgment was received, Sniff never retries automatically.
