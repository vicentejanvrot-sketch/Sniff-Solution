# Render staging deployment

The Render blueprint on phase3-automated-publishing creates only a free staging web service. It does not connect to Meta or Supabase, store tokens, or publish. No paid worker is provisioned.

1. In Render choose New > Blueprint, select Sniff-Solution and the phase3-automated-publishing branch.
2. Review render.yaml and verify the plan is Free before creating the service.
3. Confirm the build logs show the publishing tests passing and the deploy succeeds.
4. Open the actual service URL shown by Render, adding /healthz. Expected JSON: {"ok":true,"service":"sniff-publishing","publishingEnabled":false}.
5. The intended Meta redirect URI is the actual service HTTPS origin plus /auth/meta/callback. Register that exact URL in Meta Unified Login. The callback currently returns 503 deliberately; do not initiate authorization yet.

The Meta app ID and configuration ID are non-secret identifiers already set in the Blueprint. The encryption key is generated by Render; never put it in GitHub or chat. Preserve it securely. No Meta App Secret or Supabase secret is needed for this staging deploy. Later configure those directly in Render after authorization code is implemented.

The Free service can sleep and cannot guarantee scheduled publishing. Choose paid compute only after approving costs and testing. The original desktop server is never started by this Blueprint.

Do not deploy main as a public web service. Do not enable live publishing until the OAuth flow, database job claiming, private media transfer, error reconciliation and real-account tests are implemented and verified.
